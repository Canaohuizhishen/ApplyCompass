# 投递罗盘 · ApplyCompass — 设计文档

**版本**：v1.0（设计定稿）
**日期**：2026-10-14
**状态**：M1 已交付（commit `0e2187f`）；**M2 进行中**（增补见 §11）
**定位**：本地单机、Qt6/QML 的求职投递管理工具；以「方便记录投递信息」为内核。

> 一句话：点「添加」进表单、点行看详情、点状态就改——日期/归位/变色自动完成，一键导出给你手机看。

## 0. 背景与沿革（30 秒）

- 原表（WPS 表格）：录入靠戳格子、日期靠手填；宏方案因 WPS 不支持 JS 宏事件，止步于"手动触发"，体验不达标。
- 评估过现成开源（JobOps / JobSync / OfferPilot 等）：**没有合适的，决定自建**（OfferPilot 已弃用）。
- 现有数据：`投递/我的投递记录_宏版.xlsm` 共 **43 条**有效记录（已投 12 / 待投 31），本应用首批全量导入。
- 相关知识：记忆 `tracker-macro-v2`（宏版实测与行为规范）、`job-application-tracker`（数据沿革）。

## 2. 体验描述（效果 = 用户看到的）

### 2.1 一个典型早晨

打开「投递罗盘」→ 单窗口表格分两段：上段**已投区**（12 行，状态彩色块），下段**待投区**（31 行）；顶栏统计条：`总投递 12 ｜ 进行中 12 ｜ 已挂 0 ｜ Offer 0 ｜ ⚠ 待跟进 3`。

昨天在 BOSS 上投了"某某科技"：点 `n`（或「+ 添加」）→ 表单弹出 → 公司"某某科技"、岗位"后端开发实习生"、类型选"实习"、地区"成都"、渠道选"BOSS"、简历版本选"C++服务端开发"，把招聘页的**职责/要求整段粘贴**进去，状态**留空** → 确定 → 待投区末尾出现一行（无状态灰字）。

今天约到面试：**单击该行** → 右侧**详情抽屉**滑出 → 把状态改为"面试" → 保存 → 表格里该行**自动跳到已投区末尾**，投递日期列=今天、状态更新列=今天，状态块**变蓝**；抽屉里的**状态时间线**自动 +1 条。

### 2.2 详情与快改

- **单击行 = 唤出详情**（右侧滑出抽屉）：全字段可改、职责/要求/备注全文可读可编辑、跟进链接可点开（系统浏览器）、状态时间线只读展示。
- **表格里的状态块单击即可快改**（下拉 9 项；可加"确认"防误触）；改完立即变色 + 联动。
- **表格其余内容不直接编辑**（防手滑），一切修改走「表单 / 详情 / 状态块」三个入口。

### 2.3 首页提示

「待跟进 N」：状态=初筛 且 状态更新 >14 天的行 → **整行浅黄底**；点顶栏「待跟进」直接筛选。

## 3. 功能规格

### 3.1 主界面（表格）

- 单窗口，跟随系统深浅色。
- **两段式**：已投区（F 非空，按进入顺序）+ 待投区（F 空，按录入顺序），段间小标题分隔。
- **列**：公司 ｜ 岗位 ｜ 类型（实习/正式 徽标）｜ 地区 ｜ 投递日期 ｜ 渠道 ｜ 状态（彩色块）｜ 状态更新 ｜ 简历版本 ｜ 链接（图标，有链接才亮）｜ 内容点（职责/要求/备注 有无内容的小圆点提示）。
- **统计条**：总投递（状态非空数）/ 进行中（初筛+笔试+面试）/ 已挂（简历挂+笔试挂+面试挂+挂）/ Offer / 待跟进（初筛>14 天）。
- 单击行=详情；状态块=快改；整表支持选中复制文本。

### 3.2 添加入口（表单）

- 顶部「+ 添加」（快捷键 `n`）。
- 表单字段：**公司\***、**岗位名称\***、类型（实习/正式，默认"正式"）、地区、渠道（下拉 9 项）、简历版本（下拉 3 项）、跟进链接、职责（多行）、要求（多行）、备注（多行）、状态（下拉 9 项，**可留空=待投**）。
- 确定后：状态留空 → 入待投区尾；状态非空 → 直接走 §5 自动规则（双日期 + 入已投区尾）。
- 校验：公司/岗位必填；链接不强制 URL 格式。

### 3.3 详情（点行唤出）

- 抽屉形式（右侧滑出；或弹窗，实现择一）。
- 内容：基本字段编辑（同表单，含状态；薪资**仅 Offer 时显示**）、职责/要求/备注全文（纯文本，支持整段粘贴）、跟进链接（点击用系统浏览器打开）、状态时间线（时间 + 从→到，自动维护、只读）。
- 操作：保存（或即时保存，择一）、**删除该行**（二次确认）。

### 3.4 状态与颜色（沿用原表语义）

| 状态 | 颜色语义 | 备注 |
| --- | --- | --- |
| 初筛 | 灰 | 已投还没消息（海投常态） |
| 笔试 | 橙 | |
| 面试 | 蓝 | |
| Offer | 绿 | 出现「薪资」字段 |
| 简历挂 / 笔试挂 / 面试挂 / 挂 | 红 | |
| 放弃 | 深灰 | |

> 精确色值：实现时用 openpyxl 从 `投递/我的投递记录_宏版.xlsm` 的条件格式里提取，保持与原表观感一致。

### 3.5 搜索与筛选

- 搜索（`/`）：公司 / 岗位 / 地区 / 备注 模糊匹配。
- 筛选：状态、类型（实习/正式）、地区；与「待跟进」快捷筛选可叠加、可清除。

### 3.6 导出

- 「导出」按钮：生成 **xlsx**（同构原表：原有列序 + 新列（类型/职责/要求/薪资）追加在后；状态配色同 §3.4；跟进链接可点；顶部统计；冻结表头），默认输出 `投递/导出/投递罗盘_YYYY-MM-DD.xlsx`；另提供 **CSV** 一键导出。
- 用途：手机看、存档、发人；导出即是一种备份。

### 3.7 快捷键（草案）

| 键 | 动作 |
| --- | --- |
| `n` | 新增投递（表单） |
| `/` | 搜索 |
| `↑` `↓` | 变更选中行 |
| `Enter` | 打开详情 |
| `1`–`9` | 直接改选中行状态（对应 9 个状态的下拉序） |
| `Ctrl+E` | 导出 xlsx |
| `Esc` | 关闭抽屉 / 清筛选 |

### 3.8 数据与备份

- 数据 = `data/applycompass.db`（SQLite 单文件）。
- 自动备份：**每日首启 + 每次退出**各留一份，`data/backups/` 保留最近 14 份。

### 4.2 表结构（草案）

```sql
applications(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  company TEXT NOT NULL, position TEXT NOT NULL,
  kind TEXT CHECK(kind IN ('实习','正式')),
  region TEXT, apply_date TEXT, channel TEXT,
  status TEXT, status_updated TEXT, resume_version TEXT,
  link TEXT, duties TEXT, requirements TEXT, notes TEXT,
  salary TEXT,
  sort_index INTEGER,            -- 已投区/待投区内的顺序
  created_at TEXT, updated_at TEXT
);
status_events(id, application_id, from_status, to_status, at);
settings(key, value);            -- 窗口布局、筛选偏好等
```

## 5. 自动规则总表（硬性）

| 触发 | 条件 | 行为 |
| --- | --- | --- |
| 填状态 | 状态 空→非空 | 投递日期为空则置今天；状态更新=今天；行移至**已投区末尾**；记时间线；若=Offer 显示薪资 |
| 改状态 | 非空→非空（值变化） | 仅 状态更新=今天；颜色更新；记时间线；进入/离开 Offer 时显示/折叠薪资 |
| 清空状态 | 非空→空 | 行**退回待投区**（保持其在待投区内的相对顺序）；投递日期、状态更新**保留**；颜色清除；记时间线 |
| 新增（表单） | 状态留空 | 入待投区尾 |
| 新增（表单） | 状态非空 | 同「填状态」 |
| 删除 | 任何状态 | 二次确认后删除（含时间线） |

- 已投区顺序策略：默认=进入顺序；后期可选"按投递日期排序"（留设置位）、拖拽微调。

## 6. 技术方案

- **栈**：Qt 6.11.2（实测 qmake6）+ QML + SQLite（QtSql）+ CMake + Ninja。
- **表格实现**：自绘行委托（ListView/TableView），状态块内嵌下拉。
- **导出**：QXlsx（`extra/qxlsx 1.5.1.1`，pacman 直装）产出 xlsx；CSV 手写。
- **导入**：一次性解析旧 xlsm（QXlsx 读）。
- **目录**：`src/`（模型/规则/存储/导入导出）｜`qml/`（界面）｜`tests/`｜`data/`｜`docs/`。
- **测试**：QTest 覆盖规则引擎（日期/归位/退回）与导入导出解析；qmltestrunner 覆盖交互。
- **构建纪律**：一律 `--parallel 4`（本机 OOM 事故史）；交付前 **编译 + 测试全绿**。
- **版本管理**：本地 git（commit 由实现方做；**push 永远由用户手动**）。

## 11. M2 增补（2026-10-14 用户拍板）

以下为用户在 M2 开工时新增拍板，**优先于** §7 原 M2 清单并一并交付：

1. **Ctrl+滚轮缩放（Excel 式）**：范围 70%–160%、步进 10%、默认 100%；采用**全局 UI 缩放**——所有字体/行高/列宽/间距经设计令牌 × zoom（`qml/Theme.qml`），对话框与详情抽屉同步缩放；在主窗口任意处 Ctrl+滚轮生效；顶栏显示缩放百分比（点击恢复 100%）；缩放持久化到 `settings` 表。
2. **视觉刷新（用户发起）**：建立现代浅色设计令牌体系（色板见 `Theme.qml`）；**9 个状态语义色保持不变**（§3.4 旧表实测值，测试有锚定）；显式设定应用字体 `Noto Sans CJK SC`（本机 fontconfig 默认回落 Droid Sans Fallback，观感差的主因之一）；组件圆角/胶囊 chips/发丝分隔线化。动效与深浅色仍按 §7 留 M3。
3. 附加约束（口径澄清）：
   - 统计条 = **全库**口径（不随筛选变化）；分区头计数 = 筛选后计数；
   - 导出 = **全量**数据（非当前筛选视图），同日重复导出覆盖同名文件；
   - 快捷键在文本输入聚焦时自动让位（搜索框内 `n`/数字不触发命令）。
4. 导出细节澄清（对照 §3.6）：冻结表头由「导出后 ZIP 注入 `<pane>`」实现（QXlsx 1.5.1.1 无 API，注入后自检、失败降级）；CSV 采用 UTF-8 **带 BOM**（WPS 中文兼容）。
